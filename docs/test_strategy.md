# VIGIL-AI: Testing & Evaluation Strategy
**Verification Plan, Benchmark Protocols, Latency Profiling, and Test Architecture**

---

## 1. Multi-Tier Testing Pyramid

The VIGIL-AI verification suite is divided into four distinct testing layers:

```
                  +--------------------------------+
                  |   End-to-End Evaluation        |
                  |   (ASVspoof & Synthetic Test)  |
                  +---------------+----------------+
                                  |
                  +---------------+----------------+
                  |   Streaming Latency & Load     |
                  |   (P50/P95/P99 Timing Bench)   |
                  +---------------+----------------+
                                  |
                  +---------------+----------------+
                  |   Integration Tests            |
                  |   (WebSocket & REST Flow)      |
                  +---------------+----------------+
                                  |
                  +---------------+----------------+
                  |   Unit Tests                   |
                  |   (VAD, Chunker, Math, Models) |
                  +--------------------------------+
```

---

## 2. Unit Testing Layer

Unit tests are isolated, deterministic, and fast-executing (`pytest`).

### Key Test Suites:
1. **Audio Preprocessor & Normalizer (`test_preprocessor.py`):**
   - Test resampling from 8kHz, 44.1kHz, and 48kHz down to 16kHz mono.
   - Verify clipping guard prevents float overflow outside `[-1.0, 1.0]`.
   - Verify zero-retention memory overwrite: memory buffer is effectively wiped.
2. **Sliding Window Chunker (`test_chunker.py`):**
   - Ensure sliding window buffer accurately maintains 1.5s (24,000 samples) with 500ms hop (8,000 samples).
   - Test buffer starvation and rapid burst handling.
3. **Voice Activity Detection (`test_vad.py`):**
   - Verify silence / ambient noise produces `is_speech == False`.
   - Verify clean human speech produces `is_speech == True` with `latency_ms < 15ms`.
4. **Bayesian Risk & Uncertainty Engine (`test_risk_engine.py`):**
   - Test state transitions: `ALLOW`, `WARN`, `CHALLENGE`, `BLOCK`.
   - Verify that high uncertainty ($U > 0.60$) triggers `CHALLENGE` or `UNCERTAIN` even if deepfake probability is high.
   - Verify that non-enrolled calls do not fail speaker verification, but flag lack of biometric profile gracefully.

---

## 3. Integration Testing Layer

Integration tests validate the end-to-end client-server interaction over real network sockets (`pytest-asyncio` + `httpx` + `websockets`).

### Key Integration Scenarios:
1. **WebSocket Streaming Flow (`test_websocket_stream.py`):**
   - Connect client, send `CONFIG` handshake.
   - Stream 10 seconds of synthetic audio in 200ms chunks.
   - Assert server responds with valid `VERDICT` payloads every 500ms.
   - Validate payload schema completeness (decision, uncertainty, latency metrics, explainability).
2. **Android CallScreening Telephony API (`test_screening_api.py`):**
   - Simulate incoming call webhook with unverified STIR/SHAKEN status.
   - Verify response triggers `WARN` or `BLOCK` recommendations with appropriate HUD alert text.
3. **Voiceprint Enrollment & Verification (`test_enrollment.py`):**
   - Enroll 3 sample WAVs for a synthetic user profile.
   - Stream test audio of the same speaker -> Expect `is_match == True` ($S > 0.65$).
   - Stream test audio of an impersonator -> Expect `is_match == False` ($S < 0.45$).

## 4. Benchmark & Latency Profiling Harness

To guarantee real-time performance, every PR must pass an automated latency regression test:

```python
# Benchmarking Target Requirements:
MAX_ALLOWED_VAD_LATENCY_MS = 20.0
MAX_ALLOWED_ANTISPOOF_LATENCY_MS = 180.0
MAX_ALLOWED_SPEAKER_VERIFY_LATENCY_MS = 70.0
MAX_ALLOWED_TOTAL_PIPELINE_LATENCY_MS = 360.0
```

- **Harness:** Streams synthetic audio bursts through the pipeline at 1x, 2x, and 4x real-time speed.
- **Reporting:** Emits a Markdown report containing P50, P90, P95, and P99 latency percentiles.

## 5. Algorithmic Evaluation & Accuracy Benchmarking

VIGIL-AI will be benchmarked against standard public and curated datasets:

1. **ASVspoof 2019 / 2021 Logical Access (LA) & Deepfake (DF) Protocols:**
   - Evaluated metrics:
     - Equal Error Rate (EER)
     - Minimum tandem Detection Cost Function (min t-DCF)
2. **In-The-Wild Voice Cloning Benchmark:**
   - Evaluated on voices generated by:
     - ElevenLabs (multilingual v2)
     - XTTS v2 / Bark
     - OpenVoice / VALL-E
     - RVC (Retrieval-based Voice Conversion)
3. **Target Performance Metrics:**
   - Detection EER: $< 4.5\%$ on clean audio; $< 8.5\%$ on compressed AMR-NB / Opus codecs.
   - False Alarm Rate (FAR) on genuine speech: $< 2.0\%$ (prevents annoying legitimate callers).
   - Real-Time Factor (RTF): $< 0.35$ (meaning 1 second of audio is analyzed in $< 350\text{ms}$).

---

## 6. Synthetic Mock Audio Generator for Development

A test fixture (`tests/fixtures/audio_generator.py`) programmatically generates:
- Pure sinusoidal tones (frequency sweeps)
- Synthetic pink/white acoustic noise
- Pre-packaged genuine speech samples (LibriSpeech clean subset)
- Synthetically vocoded samples (HiFi-GAN synthesized audio with known phase artifacts)

This ensures the entire pipeline can be tested in CI/CD without requiring external proprietary speech datasets or live microphones.
